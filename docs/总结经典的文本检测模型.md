# 经典文本检测模型总结

## 一、问题背景与整体脉络

文本检测与通用目标检测的区别在于:文本**长宽比极端**(长文本行)、**方向多变**、**形状任意**(弯曲文本)、**尺度跨度大**,并且文本实例之间常常紧挨着。这些特点推动了方法的演进:

```
传统方法(MSER / SWT)
   ↓
基于回归(借鉴目标检测):CTPN → TextBoxes → SegLink → EAST → RRPN ...
   ↓  (遇到弯曲文本瓶颈)
基于分割:PixelLink → TextSnake → PSENet → CRAFT → PAN → DBNet
   ↓
任意形状轮廓参数化:ABCNet(贝塞尔曲线)、FCENet(傅里叶轮廓)
```

## 二、传统方法(深度学习之前)

- **MSER:** 提取亮度上"最大稳定极值区域"作为字符候选,再用规则过滤和合并。
- **SWT(笔画宽度变换):** 利用文字笔画宽度近似恒定的特性提取候选字符,再聚合成文本行。

它们依赖手工特征和多步规则,对光照、模糊、复杂背景很脆弱,现在只有历史意义。

## 三、基于回归的方法

思路是把文本当作一种特殊的目标,直接回归文本框。

| 模型 | 年份 | 核心思想 | 特点 |
|---|---|---|---|
| **CTPN** | 2016 | 把文本行拆成固定宽度(16px)的竖直小片段,用 Faster R-CNN 式 anchor 预测每个片段,再用 BLSTM 建模水平方向的上下文,最后把片段连接成文本行 | 擅长水平长文本;不能处理倾斜、弯曲 |
| **TextBoxes / TextBoxes++** | 2017/2018 | 基于 SSD,用细长的 default box 和 1×5 卷积核适应文本的大长宽比;++ 版本支持四边形/旋转框 | 单阶段,速度较快 |
| **SegLink** | 2017 | 预测文本"小段(segment)"及段间的"连接(link)",再把有连接的段组合成整行,段自带旋转角度 | 可处理多方向和长文本 |
| **EAST** | 2017 | 全卷积网络直接逐像素预测文本得分图和几何信息(旋转框 RBOX:四边距离+角度;或四边形 QUAD),再用 locality-aware NMS 合并 | 流程极简,速度快,是后来很多工作的基线;对长文本感受野不足,不支持弯曲文本 |
| **RRPN / R2CNN** | 2017/2018 | 在两阶段检测框架(Faster R-CNN)上引入旋转 anchor 或多尺度池化 | 精度较高,速度较慢 |

**共同局限:** 用矩形/四边形表示文本,遇到弯曲文本很难贴合。

## 四、基于分割的方法

思路是先做像素级预测,再通过后处理得到文本实例,天然适合任意形状。关键难点是**如何分开相邻文本**。

| 模型 | 年份 | 核心思想 | 特点 |
|---|---|---|---|
| **PixelLink** | 2018 | 对每个像素预测"是否文字"和与 8 个邻居的"是否同一实例"的链接,据此并查集合并出实例 | 用链接解决粘连;后处理较重 |
| **TextSnake** | 2018 | 把文本表示为沿**中心线**滑动的一串有半径和方向的圆盘(类似蛇身),预测文本区域、中心线及几何属性 | 能表示任意弯曲文本 |
| **PSENet** | 2019 | 预测多个由小到大的核,用最小核分开实例,再渐进式扩张到完整区域 | 精度高、擅长密集文本;后处理慢 |
| **CRAFT** | 2019 | 预测**字符级**的区域得分(高斯热图)和**字符间亲和度**得分,再把字符组合成词/行;合成数据训练后,用弱监督方式在真实数据上生成伪字符标注 | 对弯曲、大间距文本鲁棒;依赖字符级监督思路 |
| **PAN** | 2019 | 轻量骨干(ResNet18)+ 轻量特征融合,预测文本区域、核以及**相似度向量**,按向量相似度做像素聚合 | 速度和精度的折中,后处理比 PSE 快 |
| **DBNet / DBNet++** | 2020/2022 | 用可微二值化把二值化放进网络,学习自适应阈值图;推理仅需概率图 | 简单、快速、精度好,是工业界最常用的方案(如 PP-OCR 检测模型);++ 版本加入自适应尺度融合 |

## 五、任意形状轮廓的参数化方法

介于回归和分割之间:不逐像素做分割,而是直接回归轮廓的参数化表示。

- **ABCNet(2020):** 用**贝塞尔曲线**表示文本上下边界,配合 BezierAlign 提取特征,可与识别联合训练。
- **FCENet(2021):** 把文本轮廓映射到**傅里叶域**,预测傅里叶系数来重建任意形状轮廓。
- **TextBPN 等:** 先得到初始边界点,再用图网络迭代修正边界(属于较晚期的经典方案)。

## 六、常用数据集与评价

| 数据集 | 特点 |
|---|---|
| **ICDAR2015** | 自然场景、偶发拍摄,多方向四边形标注,最常用 |
| **ICDAR2013** | 水平文本,较早期 |
| **MSRA-TD500** | 中英文、长文本行,带倾斜 |
| **Total-Text / CTW1500** | **弯曲文本**专用 |
| **ICDAR2017 MLT / ReCTS** | 多语言 / 中文场景 |

评价指标是 **Precision / Recall / F-measure**,以预测框与真值框 IoU ≥ 0.5 为命中;此外,实际应用中常看 FPS。

## 七、总结对比与选择建议

| 方法类别 | 代表 | 优势 | 劣势 |
|---|---|---|---|
| 回归 | CTPN、EAST | 流程简单、速度快 | 难处理弯曲、超长文本 |
| 分割 | PSENet、PAN、DBNet、CRAFT | 任意形状、精度高 | 依赖后处理,相邻实例需特殊设计 |
| 轮廓参数化 | ABCNet、FCENet | 端到端输出轮廓,易接识别 | 参数设计和训练较复杂 |

**选型参考:**
- **工业落地、要快要稳:** DBNet(或其工程版 PP-OCR det),几乎是默认首选。
- **密集、粘连严重的文本:** PSENet / PAN。
- **字符级精细切分、间距大的文本:** CRAFT。
- **只处理水平或轻度倾斜的文档类文本:** EAST 即可,简单够用。
- **弯曲文本 + 后续接识别:** DBNet、FCENet 或 ABCNet。

**一条贯穿的主线:** 检测模型的演进,本质是在解决三个问题——**如何表示文本**(框 → 中心线 → 轮廓)、**如何分开相邻实例**(链接、多核、收缩+unclip、相似度向量)、**如何兼顾速度**(去掉重后处理,DBNet 是这一方向的集大成者)。
